Host an MKWMP server

Back to MKWMP

A Vultr VM and one command. About US$5 a month runs a server for dozens of players. You need a Vultr account, an SSH key, and a few minutes.

1. An SSH key

You log in to the VM with a key, not a password. If you don't have one, create it on your own computer (PowerShell on Windows, a terminal on macOS or Linux) and press Enter at each question:

Your public key is now in ~/.ssh/id_ed25519.pub (on Windows, C:\Users\<you>\.ssh\id_ed25519.pub). Add it at Vultr: Account → SSH Keys → Add SSH Key. Never share id_ed25519 without .pub: that's the private half.

2. The VM at Vultr

Pick a region close to most of your players: the relay and the voice and camera relay run on this VM. When it's running, note its public IPv4 address.

3. The cloud firewall

Vultr filters traffic before it reaches the VM. Create a firewall group with these inbound rules and attach it to the VM. The script opens the same ports inside the VM (ufw), so the two layers agree. Leave outbound traffic open.

ProtocolPortsFromWhat it carries
TCP22your IP (or anywhere)SSH
TCP7000anywherethe seat API: the launcher signs in and takes a seat (80 and 443 instead with a domain)
TCP8905anywherethe game's online services (TLS)
TCP8906anywhereGamesync, the game's match data
UDP3478anywherethe TURN relay, for players who can't reach each other directly
UDP49152–49407anywherethe TURN relay's sockets
UDP8907anywherevoice chat and camera relay (friend rooms)
UDP10025anywherethe NAT check

In Vultr: Network → Firewall → Add Firewall Group, add the rules, then add your VM on the group's Linked Instances tab.

4. Run the script

Log in and run it as root:

ssh root@<IPv4>
curl -fsSL https://anarqz.github.io/mkwmp/deploy-mkwmp-server.sh | sudo bash

It asks for the server's name and region, then:

  1. downloads the server from the latest MKWMP release and checks it against the release's signed checksums, with the MKWMP release key built into the script (it stops if anything doesn't match);

  2. creates the mkwmp user and /var/lib/mkwmp: keys, the gamertag database, the config and your privacy policy;

  3. installs two services, mkwmp-seat for launchers and mkwmp-lobby for the game, and keeps their logs for 7 days;

  4. opens the ports in ufw, keeping SSH open;

  5. lists the server in the server directory, so it shows up in everyone's launcher;

  6. checks that it answers from outside and that the directory lists it, then prints the address players use.

Without questions:

curl -fsSL https://anarqz.github.io/mkwmp/deploy-mkwmp-server.sh | sudo bash -s -- \
  --name "Friday kart" --region eu-west --capacity 24 --yes
Options
--namethe name in the launcher and the server list: up to 32 letters, digits, spaces and _ . -
--regiona short tag for the server list, like sa-east, us-east or eu-west
--capacityplayers seated at once (50 by default); the rest wait in a queue
--public-ipthe address players reach the VM at, if it isn't the VM's own
--domainHTTPS with Caddy (step 5)
--privacy-fileyour own privacy policy (Markdown)
--no-announcestay out of the public server list; players type your address
--versiona given release, like v1.4.0
--no-firewallleave ufw alone
--uninstallremove the services, the program and the ufw rules; keeps /var/lib/mkwmp (add --purge to delete it too)

Your privacy policy

Players see /var/lib/mkwmp/privacy.md in the launcher and accept it. The script writes a template the first time: edit it so it's true for your server (who you are, how to reach you, how long you keep logs), then run systemctl restart mkwmp-seat. Every edit is a new version, and players are asked to accept it again.

5. A domain and HTTPS (optional, recommended)

Over plain http://, PINs travel unencrypted. With a domain:

  1. Create a DNS A record, like mkw.example.net, pointing at the VM's public IPv4. At Cloudflare, make it DNS only (grey cloud) at first, so the certificate can be issued.

  2. In the cloud firewall, open TCP 80 and 443 (you can close 7000).

  3. Run the script again with --domain mkw.example.net. It installs Caddy, which gets and renews a Let's Encrypt certificate, keeps the seat API on the VM only, and lists https://mkw.example.net in the directory.

The game's own ports (8905, 8906 and the UDP ones) still go straight to the VM's IP address.

6. Updates, backups and logs
UpdateRun the script again. It remembers its options, installs the latest release and keeps gamertags, friends and keys. Restarting the lobby doesn't end running games.
Backup/var/lib/mkwmp is everything: registry.db (gamertags, PIN hashes, friends) and keys/ (your server's identity). Stop mkwmp-seat, archive the folder, start it again. Keep backups private and delete old ones: they hold your players' data.
Logsjournalctl -u mkwmp-seat -u mkwmp-lobby -f, kept for 7 days.
AdminGamertags and reports: sudo -u mkwmp /opt/mkwmp/bin/server admin list --config /var/lib/mkwmp/server.toml, and the other admin commands in the hosting guide.
7. Troubleshooting
SymptomCheck
The script stops at "signature does NOT verify"The download was altered or cut short. Run it again; don't install by hand.
"/ping did not answer from this VM"The cloud firewall isn't attached or lacks TCP 7000 (or 80 and 443 with a domain). With --domain, the A record may not point at the VM yet.
Not listed in the directoryjournalctl -u mkwmp-seat | grep announce. "HTTP 400 … endpoint" means a private address (use --public-ip); "connect" means outbound HTTPS is blocked.
Launchers connect, but the game can'tTCP 8905 and 8906 closed in the cloud firewall; systemctl status mkwmp-lobby.
Players can't race or talk togetherThe UDP ports (3478, 49152–49407, 8907, 10025) closed in the cloud firewall.
On your own PC

For friends or a LAN party, download the server zip from the latest release and run server.exe (Windows) or ./server (Linux). The first run asks for the address players reach your PC at, creates mkwmp-data next to it, and runs until you close it. Over the internet, forward the ports above on your router. Players set the launcher's server to http://<that address>:7000.
